calculator, fetch URL, unified tool guidance, bounded sequential orchestration).

## Functional verification (manual — Step 55)

Not executed in Step 54: these need a tool-capable local model and a browser.

- [ ] **(manual) Compatible local model tool test:** a tool-capable local model (recent
      qwen2.5 / llama3.x class model on llama.cpp or Ollama) actually issues tool calls.
- [ ] **(manual) Runtime context (Flow E):** the answer reflects the machine date and the
      browser timezone; malformed/omitted `runtimeContext` behaves as documented.
- [ ] **(manual) Calculator (Flow F):** correct result through the tool; non-arithmetic
      input refused with `TOOL_INVALID_ARGUMENTS`; nothing off by default is enabled.
- [ ] **(manual) Fetch URL — public page (Flow G):** a public page is read as text, gets
      an `[N]` source, and page text cannot rename a source.
- [ ] **(manual) Fetch URL — private and metadata targets (Flow G):** loopback, RFC1918,
      link-local and `169.254.169.254` are refused with a safe reason and no resolver
      detail; binary and 404 responses fail safely.
- [ ] **(manual) Web search (Flow C):** with a real Tavily key, a fresh-information prompt
      cites sources and the Sources list shows links.
- [ ] **(manual) Three-tool chain (Flow H):** `web_search` → `fetch_url` → answer,
      sequential only, ≤ 3 executions and ≤ 4 model rounds, per-tool caps honoured,
      de-duplicated stable `[N]` sources.
- [ ] **(manual) Stop / cancel mid-chain:** stopping during a tool leaves a stopped
      message with its sources and the next turn still works.
- [ ] **(manual) Disabled by default:** with all tools off, ordinary chat works, no tool is
      advertised to the model, and `POST /api/chat` still rejects tool requests.
- [ ] **(manual) Source links (Flow D):** source chips open real links, sanitized titles,
      no raw tool JSON / `tool` role / tool-call id in the transcript.

## Security & privacy review

- [ ] **(manual)** No key or secret in backend logs, SSE events, assistant messages, error
      details or source metadata during a web-search and fetch turn.
- [ ] **(manual)** No fetched/searched URL, page text, snippet, DNS record or resolved
      address appears in backend logs.
- [ ] **(manual)** `fetch_url` never follows a redirect into a private range and never
      sends cookies or provider keys.
- [ ] **(manual)** Tavily key stays browser-side: sent only while web search is enabled,
      never persisted or logged by the backend.
- [ ] **(manual)** A page containing text like `[1]`, "system" or "ignore previous
      instructions" is not treated as instructions and does not alter source attribution.
- [x] Documentation states the residual risks instead of implying a guarantee: SSRF is
      reduced and not eliminated (DNS rebinding / no connection pinning), prompt injection
      cannot be eliminated, and the app stays a single-user local tool.
