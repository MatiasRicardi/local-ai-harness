# Release Notes — Local AI Harness v1.2.0

The v1.2.0 release adds the **runtime context**, **calculator** and **fetch URL** tools on
top of the v1.0.0 chat foundation and the v1.1.0 tool-calling layer, and lets a
model chain the available tools **sequentially** inside bounded limits. It does **not**
change that foundation: chat, SSE streaming, stop/cancel, single-document context,
structured errors, temporary-file cleanup and the Docker layout are preserved, and every
new capability is off by default.

> **Status: prepared, not published.** The version metadata and documentation for
> `v1.2.0` are in place on `main`, but the GitHub tag and Release are created only
> after the Step 55 validation, and deliberately by hand. Nothing in this file should
> be read as "released" until the tag exists.

## Overview

v1.2.0 turns the single web-search tool into a small, deliberately bounded tool
system. A local model with tool-calling support can now be given three tools in the
same turn — `web_search`, `fetch_url` and `calculator` — and chain them sequentially
(search → read a page → answer) inside hard, code-level limits that the model cannot
raise. The model is also told the current date, time and timezone, generated by the
backend instead of the browser, so "today" finally means something to a static local
model. Every new **tool** is off by default, all of it is untrusted-content-first, and
the release adds no new configuration variable, dependency or storage layer, and no
network surface beyond the fetches the enabled tools perform. Alongside it, the settings
UI was reorganised into focused cards.

## Highlights

- **Runtime context.** The browser now sends its IANA timezone and locale with each
  streaming request, and the backend turns that into a server-authored system message with
  the current date, time, ISO-8601 instant and UTC offset **from its own clock**. The
  browser can never set the instant, only the zone it is displayed in, and the message is
  never returned to the browser as history.
- **Settings UI redesign.** Provider settings are split into focused cards — Connection,
  Context & Runtime, Web Search, Built-in Tools — with the **Test Connection** action in a
  pinned footer, and the empty-state prompt-suggestion cards are gone.
- **`calculator` tool.** Arithmetic through an explicit lexer and recursive-descent
  parser — numbers, `+ - * / % ^`, parentheses and unary signs, bounded by length,
  token and recursion-depth caps. There is no code-execution path at all (no `eval`,
  `new Function`, `vm`, `child_process` or dynamic `import`), and no I/O. Off by
  default.
- **`fetch_url` tool.** Retrieves the textual content of one public HTTP(S) URL for the
  model to use directly. Destination policy (protocol allowlist, no URL credentials,
  public-routable addresses only), a transport with a single deadline, manual redirects
  revalidated hop by hop, a streamed byte cap and a textual-MIME allowlist, and a
  deterministic HTML/XML/JSON extractor that never executes anything. Content is
  delivered as untrusted data with a harness-assigned `[N]` source. Off by default.
- **Bounded sequential multi-step turns.** A turn may chain tools, one call per model
  round: at most **4** model rounds and **3** tool executions per turn, with
  per-tool caps (`web_search` 1, `fetch_url` 2, `calculator` 3). Parallel tool calls
  are not supported, and the bounds are code constants, not configuration.
- **Unified capability-aware tool guidance.** One compact `system` message, owned
  entirely by the backend, is appended **after the last visible user message** and lists
  only the capabilities the request actually enabled. It states the source-attribution
  rules once (shared with `web_search`), never repeats tool schemas (the model sees them
  in the tool definitions), and is never sent back to the browser.
- **Turn-local source accumulation.** Search hits and fetched pages share one id space
  keyed by normalized URL, so a turn has stable, de-duplicated `[N]` labels no matter how
  many tools contributed.
- **Generic tool activity UI.** Activity is no longer search-only: each tool gets its own
  label ("Searching the web…", "Reading a web page…", "Calculating…"), duplicate
  activations never spawn a second card, and a stop during an active run leaves no
  stranded card. Raw tool JSON, provider `tool` roles and tool-call ids stay out of the
  transcript.
- **Cumulative tool-result budgeting.** Tool results from every round are budgeted
  against the configured context window as the turn accumulates, and the final round is
  re-budgeted, so a second tool result cannot push the conversation past the limit.
- **Same guarantees preserved.** Structured error envelope, SSE cancel semantics, upload
  validation with guaranteed temp-file cleanup, Markdown rendering sanitized through
  DOMPurify, no logging of secrets or content.

## Added

- Backend — runtime context: `runtimeContextSchema` (validated IANA timezone ≤ 100 chars,
  locale ≤ 40 chars, optional), `runtimeContextMessage()` with a strict placeholder
  contract, and the injection point in `routes/chat.ts`.
- Backend — `tools/calculatorExpression.ts` (lexer, recursive-descent parser,
  `formatCalculatorNumber()`), `tools/calculatorTool.ts` with
  `executionPolicy.maxExecutionsPerTurn = 3`.
- Backend — `tools/fetchUrlPolicy.ts` (WHATWG parsing, protocol/credential rules,
  synchronous IPv4/IPv6 classification, DNS classification that requires *every* answer to
  be public), `tools/fetchUrlClient.ts` (deadline, manual redirect loop, streamed byte
  cap, MIME allowlist, fixed harness-controlled headers), `tools/fetchUrlContent.ts`
  (deterministic HTML/XML/JSON → text), `tools/fetchUrlTool.ts`.
- Backend — orchestration: `orchestration/chatOrchestrator.ts` (bounded sequential tool
  loop, forced no-tools final round), `orchestration/toolCallValidation.ts` (strict
  per-tool argument schemas, per-turn caps), `orchestration/turnSources.ts`
  (`TurnSourceAccumulator`, turn-local atomic id allocation keyed by normalized URL).
- Backend — `tools/registry.ts` composition, `tools/untrustedContent.ts` (shared
  untrusted-web-content boundary) and `utils/toolGuidance.ts`
  (`resolveToolCapabilities()`, `buildToolGuidanceMessage()`,
  `appendToolGuidanceAfterLastUserMessage()`, `ToolCapability` / `EnabledToolName`).
- Backend — `context/toolResultBudget.ts` for cumulative input budgeting, with
  `TOOL_RESULT_CONTEXT_OMISSION_TEXT` for results that cannot be included.
- Backend — four error codes: `TOOL_NOT_FOUND`, `TOOL_INVALID_ARGUMENTS`,
  `TOOL_EXECUTION_FAILED`, `TOOL_CALL_LIMIT_EXCEEDED` (all mirrored in
  `frontend/src/utils/parseApiError.ts`).
- Frontend — `utils/runtimeContext.ts` (`buildRuntimeContext()`: reads the browser's IANA
  timezone and locale through `Intl` and returns `undefined` instead of ever throwing, so a
  collection failure cannot break chat), `components/BuiltInToolSettings.vue` and
  `composables/useToolSettings.ts` (Calculator and Fetch URL toggles, persisted in
  `localStorage`), and the `runtimeContext` / `calculator` / `fetchUrl` request fields.
- Frontend (UI redesign, PR #37) — `ConnectionSettings.vue`, `RuntimeSettings.vue`
  (context size, timeout and API key), `WebSearchSettings.vue`, `ConnectionTestFooter.vue`
  and `composables/useConnectionTest.ts`.
- Frontend — generic tool activity labels and per-tool lifecycle handling in
  `services/chat.ts` and `App.vue`.
- Docs — this release, its checklist, and `AGENTS.md` / `README.md` /
  `docs/architecture.md` / `docs/security.md` / `docs/smoke-test.md` updates (Flows E–H).

## Changed

- **Web Search is now a tool among tools.** `web_search` registers through the same
  request-scoped registry as the new tools, and its per-turn cap is expressed as the
  generic `executionPolicy.maxExecutionsPerTurn = 1` rather than as a search-specific
  special case. `web_search` remains the only capability whose guidance references
  supplied URLs (`urlsSupplied`): the "search first" rule is suppressed when the user
  already supplied URLs.
- **One guidance message instead of a search-only addendum.** `WEB_SEARCH_GUIDANCE` and
  `appendWebSearchGuidance()` are deprecated aliases over the new unified module. The
  injection point moved so tool guidance always sits after the last user-authored message
  and never inside the historical prefix.
- **Source identity is harness-owned.** Ids come from one accumulator keyed by normalized
  URL, so `web_search` and `fetch_url` never allocate twice for the same document, and
  delivery of the untrusted-content marker is decided by what was actually sent.
- **Streaming turns are generic.** `tool_start` / `tool_end` / `sources` now describe any
  enabled tool, with type-specific UI labels and source types (`search | fetch |
  generated`).
- **Request-scoped tool opt-in.** `ChatRequest.tools` carries `calculator` and `fetchUrl`
  (both off by default) alongside the existing `webSearch` object and `runtimeContext`.
- **Settings UI layout.** The single settings panel became a column of cards (Connection /
  Context & Runtime / Web Search / Built-in Tools) with a pinned Test Connection footer, and
  the empty state no longer offers suggestion cards. Existing provider, model, context and
  Web Search settings keep their `localStorage` keys and behaviour.
- **Documentation**: `README.md` no longer states that no result pages are fetched (that
  was true of `web_search` alone), and `docs/security.md` gains runtime-context,
  calculator, fetch-URL/SSRF and prompt-injection sections; `docs/architecture.md` gains
  a "Tool execution limits" table.

## Fixed

- Backend: source-id allocation is atomic and idempotent per normalized URL, and
  untrusted-marker delivery is derived from the content actually sent rather than from a
  side map that could drift.
- Backend: the forced no-tools final round is streamed live instead of buffered.
- Backend: UTC offset computed correctly for zones east of `+12:00`.
- Backend: a number with an exponent but no mantissa digits is rejected as malformed
  instead of evaluating to the wrong value.
- Backend: `fetch_url` extraction tokenizes comments, CDATA and `DOCTYPE` correctly,
  preserves `\s` escapes in the closing-tag matcher, and replaces only lone high
  surrogates.
- Backend: the `fetch_url` transport no longer leaves a window where a slow header
  validation or an unread body could outlive the deadline.
- Frontend: a connection-test completion that arrives after a newer test (or a cleared
  form) no longer overwrites the current status.

## Breaking changes

No breaking changes.

- Existing requests keep working: `runtimeContext`, `webSearch` and `tools` are all
  optional, and every tool stays off when omitted.
- No environment variables were added or removed.
- No storage or migration concerns (browser `localStorage` keys are additive; there is no
  database).
- Existing UI settings (provider, model, context, Web Search) keep their stored values.

## What is *not* part of v1.2.0

- No new runtime dependencies in `backend/`, `frontend/` or the workspace.
- No contract change beyond the additive request fields above; no new route.
- No new `AI_*` configuration variable.

## Configuration

v1.2.0 adds **no** new environment variable. The existing `AI_*` set is unchanged (see the
config table in [`docs/architecture.md`](../architecture.md#configuration)), and the
Tavily endpoint keeps its `AI_TAVILY_BASE_URL` default while the Tavily API key stays a
browser-side value rather than a `.env` entry.

The new behaviour is configured where it is used:

| Setting | Where | Default |
|---------|-------|---------|
| Runtime context | No toggle: the browser sends `runtimeContext` (timezone + locale) on streaming requests when `Intl` provides it | Always sent when available |
| Calculator | UI toggle (browser `localStorage`), sent as `tools.calculator` | Disabled |
| Fetch URL | UI toggle (browser `localStorage`), sent as `tools.fetchUrl` | Disabled |
| Orchestration and tool bounds | Code constants | See [Tool execution limits](../architecture.md#tool-execution-limits) |

## What did not change

- Chat, SSE streaming, and stop/cancel semantics for plain turns.
- Single-document context (`.txt`, `.md`, `.pdf`) and context-size configuration.
- Structured error envelope and end-to-end error handling.
- Temporary-file lifecycle and cleanup.
- Docker Compose layout and the same-origin `/api` proxy.
- The provider test endpoint, and `POST /api/chat` (which still runs no tools).

## Known limitations and planned improvements

- **Runtime context has no switch.** Unlike the tools, it is not user-toggleable: the
  browser's timezone and locale accompany streaming requests whenever `Intl` reports them.
  They are coarse, user-visible system settings rather than identity or precise location,
  and a request without them is fine (the backend message falls back to UTC).
- **No web search without Tavily.** There is still no `GET /api/search/providers`
  discovery endpoint, so the provider list is compiled in and only `tavily` is supported.
- **The API key stays in the request body and browser `localStorage`.** Acceptable for a
  single-user local developer tool; it should not become a pattern for a remote
  deployment.
- **Tool use depends on the local model.** A model that never emits tool calls will
  simply answer without tools; identical prompts may or may not trigger tools. v1.2.0
  tunes nothing about model sampling, and no tool-call rate is guaranteed.
- **One tool per model round.** Parallel tool calls are out of scope: the assistant
  message that carries several `tool_calls` has no valid history if only some are
  answered.
- **`fetch_url` is not general web scraping.** No JavaScript execution, no cookies, no
  logins, no search-result processing, no automatic pagination or crawling, no PDF
  parsing, no image/binary analysis, no OCR, no arbitrary response headers, and no
  caching or persistence.
- **`fetch_url` is not a guarantee against SSRF.** DNS rebinding is documented in
  `docs/security.md` rather than closed: addresses are validated before connecting but
  the connection is not pinned to the validated answers.
- **Prompt injection cannot be eliminated.** Search snippets, fetched pages and uploaded
  documents are all untrusted input; the system guidance and untrusted boundaries reduce
  the chance the model obeys embedded instructions, and code enforces what a model cannot
  talk its way into.
- **Calculator bounds are deliberate.** 500 characters / 256 tokens / depth 64; no
  variables, functions, constants, units, percentages, matrices, dates, currency,
  arbitrary precision or symbolic simplification. IEEE-754 doubles mean very large or
  very small magnitudes can be inexact.
- **Conversation state still lives only in browser memory and `localStorage`.** There is
  no backend persistence, no cross-device history, and no persistence of tool state
  across turns.
