# Release Checklist — Local AI Harness v1.1.0

Pre-release verification for the Web Search / v1.1.0 release. Mark each item once done.
Items marked **(manual)** require a real environment and are not covered by CI.

## Build & quality gate

- [ ] Backend tests pass: `pnpm --filter backend test` (or `pnpm test` at root)
- [ ] Frontend tests pass: `pnpm --filter frontend test`
- [ ] Type checking green: `pnpm typecheck` (backend `tsc --noEmit`, frontend `vue-tsc`)
- [ ] Linting green: `pnpm lint`
- [ ] Build succeeds: `pnpm build`
- [ ] Version bumped to `1.1.0` in root, backend, and frontend `package.json` (and lockfile up to date)

## Functional verification (manual)

- [ ] **Compatible local model tool test:** a tool-capable local model (e.g. a recent
      qwen2.5/llama3.x variant on llama.cpp or Ollama) actually invokes `web_search`.
- [ ] **Real Tavily smoke test:** with a real Tavily key, a fresh-information prompt
      returns an answer that cites sources, and the **Sources** section lists links.
- [ ] **Disabled by default:** with Web Search off, ordinary chat works and no search runs.
- [ ] **Basic / Advanced:** both depths run; `advanced` may issue more requests.
- [ ] **Cancellation:** **Stop** halts an in-progress search and generation.
- [ ] **UI:** Web Search settings panel accepts the key; no Base URL field is exposed.

## Security & privacy review

- [ ] **Key leakage review:** the API key never appears in backend logs, SSE events,
      assistant messages, error details, or source metadata.
- [ ] **Key scope:** the key is stored only in the browser and sent to the backend only
      while web search is enabled; not persisted or logged on the backend.
- [ ] **Base URL ownership:** `AI_TAVILY_BASE_URL` is backend-configured, not in the UI,
      not hardcoded in the provider; HTTPS enforced on the search path.
- [ ] **Env config verification:** `AI_TAVILY_BASE_URL` is documented in
      `backend/.env.example` and the architecture config table; default applies.
- [ ] **Untrusted content:** search results are treated as reference data, not
      instructions; no arbitrary result URLs are fetched.

## Documentation

- [ ] README describes Web Search (optional, Tavily, UI key, backend Base URL, disabled
      by default, tool-call requirement) and Web Search / Tool calling are removed from
      the roadmap.
- [ ] `AI_TAVILY_BASE_URL` is documented; API-key ownership (UI, not `.env`) is clear.
- [ ] "Fully local" wording is qualified (query leaves the local environment).
- [ ] Architecture and security docs match the implementation.
- [ ] Tool-compatibility caveat is clear (not all local models support tools).
- [ ] Docs links (architecture, security, smoke test, Tavily docs/pricing) resolve.

## Docker (if available)

- [ ] `docker compose up --build` starts; web search works with the model server
      reachable via `host.docker.internal` (or equivalent).
